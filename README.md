# সাকুরা পোর্টাল (Sakura Portal)

সাকুরা জাপানিজ ইনস্টিটিউটের ছাত্র, ফি, হাজিরা আর কাগজপত্রের হিসাব রাখার নিজস্ব পোর্টাল।
শুধু ডিরেক্টর আর অফিসের স্টাফরা লগইন করে ব্যবহার করবেন।

## ফাইলগুলো

- `index.html`, `style.css`, `app.js` — পোর্টাল
- `manifest.webmanifest`, `sw.js`, `icons/` — ফোনে অ্যাপের মতো ইনস্টল করার জন্য
- `config.js` — Supabase-এর ঠিকানা আর key এখানে বসবে
- `supabase-schema.sql` — ডেটাবেসের টেবিল আর নিরাপত্তার নিয়ম (নতুন প্রজেক্টে এটাই চালান)
- `web/index.html` — সাকুরার ওয়েবসাইট আর ভর্তির ফর্ম
- `supabase-migration-v12.sql` — ছুটি আর ক্যালেন্ডারের জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v11.sql` — ওয়েবসাইটের ফর্মের জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v10.sql` — প্রসেসিং ফি আর কমিশনের জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v9.sql` — আবেদনের কাগজের তথ্যের জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v8.sql` — অভিভাবকের পাতার জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v7.sql` — কাজের রেকর্ডের জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v6.sql` — শিক্ষক আর বেতনের জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v5.sql` — কাগজের মেয়াদ আর ইস্যুর তারিখের ঘর যোগ করার জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v4.sql` — জাপানি স্কুল আর আবেদনের টেবিল যোগ করার জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v3.sql` — পরীক্ষা আর নম্বরের টেবিল যোগ করার জন্য (একবার চালানো হয়ে গেছে)
- `supabase-migration-v2.sql` — আগের প্রজেক্টে খরচ আর আগ্রহী ছাত্রের টেবিল যোগ করার জন্য (একবার চালানো হয়ে গেছে)

## ধাপ ০ — আগে ডেমো চালিয়ে দেখুন

`config.js` খালি থাকলে পোর্টাল ডেমো মোডে চলে, তথ্য শুধু ব্রাউজারে থাকে।
VS Code-এ ফোল্ডারটা খুলে **Live Server** দিয়ে `index.html` চালান →
"ডেমো মোডে ঢুকুন" → সেটিংস → "ডেমো তথ্য যোগ করুন"।

## ধাপ ১ — Supabase প্রজেক্ট খুলুন (ফ্রি)

1. https://supabase.com → Start your project → GitHub দিয়ে সাইন ইন।
2. **New project** → নাম `sakura-portal`, একটা শক্ত Database password (কোথাও লিখে রাখুন),
   Region: **Northeast Asia (Tokyo)** বা **Southeast Asia (Singapore)**।
3. প্রজেক্ট তৈরি হলে বাঁ দিকে **SQL Editor** → **New query** → `supabase-schema.sql`-এর পুরোটা পেস্ট → **Run**।
   "Success" দেখালে টেবিল আর নিরাপত্তার নিয়ম তৈরি।

## ধাপ ২ — নিজের লগইন বানান

1. **Authentication → Users → Add user → Create new user** →
   ইমেইল `sayemahmed8820@gmail.com`, একটা পাসওয়ার্ড, **Auto Confirm User** টিক দিন।
2. **SQL Editor**-এ চালান (নিজেকে অ্যাডমিন বানানো):

```sql
insert into public.profiles (id, name, role)
select id, 'Sayem Ahmed', 'admin' from auth.users where email = 'sayemahmed8820@gmail.com';
```

3. **Authentication → Sign In / Providers → Email** → **Allow new users to sign up** বন্ধ করুন।
   এতে বাইরের কেউ নিজে থেকে অ্যাকাউন্ট খুলতে পারবে না।

## ধাপ ৩ — পোর্টালকে Supabase-এর সাথে যুক্ত করুন

**Project Settings → API** থেকে **Project URL** আর **anon public** key কপি করে `config.js`-এ বসান:

```js
window.SAKURA_CONFIG = {
  SUPABASE_URL: "https://xxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi..."
};
```

> ⚠️ **service_role** key কখনো `config.js`-এ বা GitHub-এ দেবেন না। anon key পাবলিক হলেও সমস্যা নেই,
> কারণ ডেটা সুরক্ষিত থাকে ডেটাবেসের নিয়ম দিয়ে: লগইন করা স্টাফ ছাড়া কেউ কিছু দেখতে পারে না।

## ধাপ ৪ — অনলাইনে তুলুন (GitHub Pages)

1. GitHub-এ নতুন repository: `sakura-portal`।
2. এই ফোল্ডারের ফাইলগুলো push করুন:

```bash
cd ~/Documents/projects/sakura-portal
git init && git add . && git commit -m "Sakura portal"
git branch -M main
git remote add origin https://github.com/<আপনার-username>/sakura-portal.git
git push -u origin main
```

3. Repository → **Settings → Pages** → Branch: `main` / root → Save।
   কয়েক মিনিট পর লিংক পাবেন: `https://<username>.github.io/sakura-portal/`

## স্টাফ যোগ করা

পোর্টালে তিন ধরনের লগইন আছে, আর ছাত্রদের জন্য আলাদা ছাত্রদের সাইট:

| ভূমিকা | `role` | কে |
|---|---|---|
| পরিচালক | `admin` | সব কিছু |
| অফিস স্টাফ | `staff` | ভর্তি, টাকা জমা, কাগজ, জাপান আবেদন, আগ্রহী ছাত্র, হাজিরা, পরীক্ষা |
| শিক্ষক | `teacher` | শুধু ক্লাসের কাজ: হাজিরা, পরীক্ষা ও নম্বর, পড়ার উপকরণ, মক টেস্ট, ক্যালেন্ডার |

**যোগ করা (SQL লাগে না):** পোর্টালে **স্টাফ ও শিক্ষক** (শুধু পরিচালক দেখেন) → **+ নতুন শিক্ষক / স্টাফ** → নাম, ইমেইল, ভূমিকা → ৮ অক্ষরের আমন্ত্রণ কোড তৈরি হয় → "পাঠান" চেপে WhatsApp-এ নিয়ম আর কোড পাঠান। সে পোর্টাল খুলে **"প্রথমবার? অ্যাকাউন্ট খুলুন"** চেপে সেই ইমেইল, নিজের পাসওয়ার্ড আর কোড দেবে — তারপরই ঢুকতে পারবে। কোড শুধু সেই ইমেইলে, ১৪ দিন কাজ করে; ঘণ্টায় ৫ বারের বেশি ভুল কোড দেওয়া যায় না।

**বদলানো / বন্ধ করা:** একই পাতায় ভূমিকা বদলানো যায়, আর "লগইন বন্ধ করুন" চাপলে সে আর ঢুকতে পারে না (আগের কাজের রেকর্ড থেকে যায়)। শেষ পরিচালককে সরানো বা নামানো যায় না।

**শিক্ষকরা নিজেরা যা মুছতে পারেন:** পড়ার উপকরণ, মক টেস্টের প্রশ্ন, আর যে পরীক্ষা বা মক টেস্টে এখনো কারো নম্বর/চেষ্টা নেই। নম্বর থাকা জিনিস শুধু পরিচালক মুছতে পারেন।

## ছাত্রদের সাইট ও পড়ার উপকরণ

ছাত্রদের সাইটের ঠিকানা: পোর্টালের ঠিকানার শেষে `student/` (যেমন `https://sayemahmed-jp.github.io/sakura-portal/student/`)।

**উপকরণ যোগ করা:** পোর্টালে **পড়ার উপকরণ** → **+ নতুন উপকরণ**। নাম, লেভেল (N5/N4/N3/সব লেভেল), অধ্যায় আর ক্রম দিন, তারপর PDF/অডিও/ভিডিও/ছবি আপলোড করুন অথবা YouTube/Drive লিংক দিন। প্রতিটা ফাইল সর্বোচ্চ ৫০ MB; ফ্রি প্ল্যানে কাগজপত্রসহ মোট ১ GB। বড় ভিডিও YouTube-এ Unlisted করে লিংক দিন।

**ছাপানো বইয়ের PDF বা অডিও (Minna no Nihongo, Genki ইত্যাদি) রাখবেন না** — কপিরাইট আইনের লঙ্ঘন। নিজেদের বানানো নোট, শিট, শব্দতালিকা, মডেল টেস্ট আর নিজেদের রেকর্ডিং রাখুন।

**ছাত্র কীভাবে ঢোকে:**
1. ছাত্রের পাতায় **ছাত্রদের সাইট** → **নিয়ম WhatsApp-এ পাঠান**।
2. ছাত্র সাইটে **নতুন অ্যাকাউন্ট** খোলে (নিজের ইমেইল + পাসওয়ার্ড)।
3. **ভর্তি নম্বর** আর ভর্তির সময় দেওয়া **মোবাইল নম্বর** (নিজের বা অভিভাবকের) দিয়ে যুক্ত করে। ভুল হলে ঘণ্টায় ৫ বার পর্যন্ত চেষ্টা করা যায়।

**কে কী দেখে:** ছাত্র শুধু নিজের প্যাকেজের লেভেল (যেমন N5+N4 হলে N5 আর N4) আর "সব লেভেল"-এর উপকরণ দেখে — তাও শুধু যখন **পুরো কোর্স ফি পরিশোধ** হয়েছে, অবস্থা "বাদ দিয়েছে" নয়, আর অফিস অ্যাক্সেস বন্ধ রাখেনি। টাকা জমা লিখলেই নিজে থেকে খুলে যায়। এই নিয়ম ডাটাবেস (v14) মেনে চলে, তাই লিংক জানলেও কেউ অন্যের বা বন্ধ থাকা ফাইল খুলতে পারে না। ফাইলের লিংক ১ ঘণ্টা পর অচল হয়।

**ছাত্রের লগইন সমস্যা:** পাসওয়ার্ড ভুলে গেলে সাইটের "পাসওয়ার্ড ভুলে গেছেন?" ইমেইল পাঠায় — এজন্য Supabase-এ নিজের ইমেইল সার্ভিস (Custom SMTP) চালু থাকতে হয়। না থাকলে অ্যাডমিন ছাত্রের পাতায় **ছাত্রদের সাইট → লগইন আলাদা করুন** চাপুন; ছাত্র অন্য ইমেইল দিয়ে নতুন অ্যাকাউন্ট খুলে আবার যুক্ত করবে।

**ব্যাকআপ:** পুরো ব্যাকআপে উপকরণের তালিকা থাকে, কিন্তু উপকরণের ফাইলগুলো থাকে না — মূল ফাইলগুলো নিজের কম্পিউটার/Drive-এ রেখে দিন।

## অনলাইন মক টেস্ট

পোর্টালে **মক টেস্ট** পাতা থেকে টেস্ট বানানো যায় (লেভেল, সময়, পাস নম্বর %, কতবার দেওয়া যাবে)। প্রশ্নের চারটা ভাগ: শব্দ ও কানজি, ব্যাকরণ, পড়া (読解), শোনা (聴解)।

- **প্রশ্ন যোগ:** টেস্টের পাতায় "+ প্রশ্ন", অথবা **CSV থেকে প্রশ্ন** (নমুনা ফাইল সেখান থেকে নামানো যায়)। কলাম: `section, passage, question, option1–4, correct (১–৪), explanation, script`।
- **শোনার প্রশ্ন:** জাপানি স্ক্রিপ্ট লিখলে ছাত্রের ফোন সেটা জাপানি ভয়েসে পড়ে শোনায়; চাইলে নিজের রেকর্ড করা অডিও তুলুন (সেটাই ভালো)।
- **ছাত্র কী দেখে:** নিজের লেভেলের চালু টেস্ট, পুরো কোর্স ফি দেওয়া থাকলে। টাইমার চলে, উত্তর নিজে থেকে সেভ হয়, সময় শেষে নিজে থেকেই জমা হয়। সঠিক উত্তর জমা দেওয়ার আগে ছাত্রের ফোনে যায় না — নম্বর ডাটাবেসে গোনা হয়। জমার পর নম্বর, ভাগ অনুযায়ী ফল আর (চাইলে) সঠিক উত্তর ও ব্যাখ্যা দেখে।
- **ফলাফল:** টেস্টের পাতায় "ফলাফল" ট্যাবে; আর প্রত্যেক ছাত্রের সেরা নম্বর নিজে থেকেই **পরীক্ষা ও রেজাল্ট**-এ "অনলাইন মক: …" নামে ওঠে (অভিভাবকের পাতাতেও দেখা যায়)।
- **নমুনা প্রশ্ন:** N5-এর ৩টি আর N4-এর ৩টি মক টেস্ট (প্রতিটায় ৩০টি প্রশ্ন) সাকুরার জন্য নতুন করে লেখা — `supabase-mock-samples.sql`। এগুলো **লুকানো** অবস্থায় যোগ হয়; শিক্ষক একবার দেখে নিয়ে "ছাত্রদের জন্য চালু করুন" চাপবেন।
- **আরও টেস্ট (দ্বিতীয় দফা):** প্রতি লেভেলে মোট ১০টি পূর্ণ মক, ২০টি কানজি (পড়া, লেখা, অর্থ) আর ২০টি ব্যাকরণ টেস্ট — `supabase-mock-round2-n5.sql`, `supabase-mock-round2-n4.sql` (আগে `supabase-migration-v19.sql` চালাতে হবে)। ব্যাকরণ টেস্টে কিছু প্রশ্ন অন্য টেস্টেও ফিরে আসে। সবই লুকানো অবস্থায় যোগ হয়।
- **ভাগ:** প্রতিটা টেস্টের একটা ভাগ আছে — পূর্ণ মক, কানজি, ব্যাকরণ, শোনার অনুশীলন। পোর্টাল আর ছাত্রদের সাইট দুটোতেই টেস্টগুলো ভাগ অনুযায়ী আলাদা দেখায়। পোর্টালে লেভেল আর ভাগ বেছে "দেখানো …টি চালু করুন" দিয়ে একসাথে অনেকগুলো চালু করা যায়।
- **শোনার অনুশীলন:** "N5/N4 শোনার অনুশীলন ১" খালি টেস্ট তৈরি থাকে; নিজের রেকর্ড করা অডিও "+ প্রশ্ন" দিয়ে বসিয়ে চালু করলেই ছাত্ররা পাবে। খালি টেস্ট ছাত্ররা কখনো দেখে না।
- **পরিচালক/শিক্ষকের প্রিভিউ:** পোর্টালের লগইন দিয়ে ছাত্রদের সাইটে ঢুকলে প্রিভিউ খোলে — সব লেভেলের উপকরণ আর সব মক টেস্ট (লুকানোগুলো চিহ্নসহ) দেখা যায়, টেস্ট দিয়েও দেখা যায়; নম্বর কোথাও জমা হয় না।
- **HTML বই:** "পড়ার উপকরণ"-এ HTML ফাইল আপলোড করলে সেটা "বই" হিসেবে যোগ হয় (`supabase-migration-v20.sql`)। ছাত্র "📖 পড়ুন" চাপলে পুরো ইন্টারঅ্যাক্টিভ বই (জাপানি উচ্চারণ, অনুশীলন) খোলে; ফাইলটা অন্য উপকরণের মতোই ব্যক্তিগত স্টোরেজে থাকে, শুধু ফি পরিশোধ করা ছাত্ররা খুলতে পারে।
- **আজকের পড়া ও টানা দিনের হিসাব:** ছাত্রদের সাইটে প্রতিদিন নিজের লেভেলের ৫টি শব্দ, ১টি কানজি আর ১টি ব্যাকরণ প্রশ্ন (`student/daily.js`, সাকুরার নিজের তালিকা থেকে)। "শেষ করেছি" চাপলে বা অনলাইন মক টেস্ট দিলে দিনটা গোনা হয়; উপরে টানা কত দিন আর গত ৭ দিনের হিসাব দেখায় (`supabase-migration-v21.sql`)।
- **ফ্ল্যাশকার্ড:** ছাত্রদের সাইটে শব্দ আর কানজির কার্ড (N5/N4)। "জানি" চাপলে কার্ড ১ → ৩ → ৭ → ১৪ → ৩০ দিন পরে ফিরে আসে, "জানি না" চাপলে আজই আবার আসে; দিনে ১০টি নতুন কার্ড। হিসাব ছাত্রের নিজের ফোন/কম্পিউটারে থাকে। একটা দফা শেষ করলে সেটাও পড়ার দিন হিসেবে গোনা হয়।

- **ক্লাসের মতামত:** মাসের ১৫ তারিখ থেকে ছাত্ররা ছোট জরিপ দেয় (ক্লাস ও বোঝানো ★, গতি, বাড়ির কাজ, মন্তব্য); পোর্টালের "ছাত্রদের মতামত" পাতায় নাম ছাড়া ফলাফল, শুধু পরিচালক ও অফিস দেখেন (`supabase-migration-v36.sql`)
- **বন্ধুকে আনুন:** প্রত্যেক ছাত্রের নিজের রেফারেল লিংক (WhatsApp-এ পাঠানো যায়); ওই লিংকে কেউ ফর্ম পূরণ করলে "আগ্রহী ছাত্র"-তে রেফারকারীর নামসহ আসে, ছাত্র দেখে কে কতদূর এগোল; পুরস্কারের কথা সেটিংসে (`supabase-migration-v37.sql`)
- **ছাত্রদের সাইটের মেনু:** মোবাইলে নিচে অ্যাপের মতো ৫টা বোতাম (হোম · পড়া · টেস্ট · জাপান · আমি), ল্যাপটপে বাম পাশের মেনু
- **ছাত্রদের কাগজ স্ক্যান:** ছাত্র "জাপান → আমার কাগজপত্র" থেকে ফোনে প্রতিটা পাতার ছবি তোলে, সব মিলে একটা PDF হয়ে অফিসে জমা হয়; পোর্টালের "ছাত্রদের পাঠানো কাগজ" থেকে দেখা, ✓ যাচাই, ↩ কারণসহ ফেরত, আর এক চাপে সব কাগজ ZIP (`supabase-migration-v38.sql`)
- **আইডি / QR:** পোর্টালের "আইডি / QR দিয়ে খুঁজুন" পাতায় ক্যামেরায় আইডি কার্ড বা ছাত্রের ফোনের ডিজিটাল আইডির QR ধরলে বা আইডি নম্বর লিখলে সাথে সাথে ছাত্রের পাতা; ছাত্রের পাতায় "📄 সম্পূর্ণ ফাইল" (সব তথ্য এক পাতায়, প্রিন্ট বা PDF); ছাত্রদের সাইটে "আমি → আমার ডিজিটাল আইডি"
- **স্টাফ ও শিক্ষকের আইডি কার্ড:** প্রত্যেক লগইনের জন্য নিজে থেকে আইডি নম্বর (SJI-D/S/T-001); পরিচালক "স্টাফ ও শিক্ষক" পাতা থেকে সবার কার্ড দেখেন ও প্রিন্ট করেন, বাকিরা মেনুর "🪪 আমার আইডি কার্ড" থেকে শুধু নিজেরটা; ছাত্রদের কার্ড প্রিন্টও শুধু পরিচালক (`supabase-migration-v39.sql`)
- **উপ-পরিচালক:** নতুন ভূমিকা — পরিচালকের মতো সব তথ্য ও কাজ (ফি, রিপোর্ট, খরচ, সেটিংস), শুধু স্টাফ যোগ করা, ভূমিকা বদলানো আর অন্যের আইডি কার্ড পরিচালকের হাতে (`supabase-migration-v40.sql`)
- **নিজে থেকে হালনাগাদ:** পরিচালকের নাম সেটিংস আর আইডি কার্ড/লগইনে একসাথে বদলায়; শিক্ষক তালিকা আর লগইন (একই ইমেইল) নাম-ফোনে মিলে থাকে; পোর্টাল বা ছাত্রদের সাইটে ফিরে এলে নতুন তথ্য নিজে থেকে লোড হয় (`supabase-migration-v41.sql`)

## প্রথমবার চালুর পর

- **সেটিংস**-এ অফিসের ঠিকানা বসান (রশিদ আর সার্টিফিকেটে যাবে)।
- সপ্তাহে একবার **রিপোর্ট → পুরো ব্যাকআপ নিন** চেপে ZIP ফাইলটা ল্যাপটপ আর Google Drive-এ রাখুন (৭ দিন না নিলে ড্যাশবোর্ড মনে করিয়ে দেয়)। ZIP-এ সব তথ্য, Excel ফাইল আর আপলোড করা কাগজ থাকে। Supabase-এর ফ্রি প্ল্যানে নিজে থেকে কোনো ব্যাকআপ থাকে না।
- Supabase-এর ফ্রি প্ল্যানে টানা ৭ দিন কেউ ব্যবহার না করলে প্রজেক্ট ঘুমিয়ে যায়;
  ড্যাশবোর্ড থেকে **Restore** চাপলে আবার চালু হয়। রোজ ব্যবহার করলে এটা হবে না।
- ফ্রি প্ল্যানে ৫০০ MB ডেটা আর ১ GB ফাইল রাখা যায়; শুরুতে এটা যথেষ্ট।
